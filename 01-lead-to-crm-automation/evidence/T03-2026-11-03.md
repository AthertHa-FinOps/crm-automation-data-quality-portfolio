# T03 — Missing-email rejection (local n8n test)

**Observed on:** November 3, 2026, 17:44:29 (local Toronto time; n8n execution display)  
**Workflow:** Real Estate Lead-to-CRM (portfolio v0.1), imported 23-node version  
**Environment:** Docker-hosted local n8n, `http://localhost:5678`; exact n8n version not recorded  
**n8n execution:** #6, displayed as "Succeeded in 953ms"  
**Result:** **PASS — validation/rejection path only**

## Request and actual response

PowerShell submitted a fictional lead with no email to the temporary test webhook:

```powershell
$body = '{"first_name":"Test","last_name":"Lead","phone":"4165550105"}'
Invoke-WebRequest -Uri "http://localhost:5678/webhook-test/lead-intake" -Method POST -ContentType "application/json" -Body $body
```

Observed HTTP status: **422**.

```json
{"status":"rejected","errors":["MISSING_EMAIL"]}
```

This matches the expected response for a missing email. The n8n execution screenshot showed the highlighted route:

`Lead Webhook → Validate & Normalize → Valid? → Outcome Rejected → Respond 422`

The `Audit Log Rejected` branch was also highlighted. No HubSpot search, create or update node appeared on the executed path. The execution's "Succeeded" label means the workflow handled the rejection without an unhandled workflow error; it does not mean the lead was accepted.

## Test setup observation

The first request returned HTTP 404 with an n8n message that `lead-intake` was not registered. After starting the temporary test listener again, the next request received HTTP 422. This was a listener-registration/setup issue; it is not evidence of a failure in the email-validation logic.
